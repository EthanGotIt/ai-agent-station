# P1：结算与续跑解耦

## 前置条件

P0 完成，当前基线和遗留失败已区分。复核 Worker、Workflow 结果投影、续跑网关和前端状态来源。

## 执行

1. 从 continuation 创建中拆出命令结算、Workflow 状态投影和业务结果 Item 写入。
2. 命令状态、Workflow 状态、核验结果及业务 Item 在同一本地事务提交；模型和远程查询在事务外。
3. 无 continuation 时仍完整写入结果；重复结算遵守 CAS/幂等边界。
4. 用 Run 已持久化的不可变编排版本选择交付策略：现有 LEGACY/V1/V2 保持兼容；P3 引入的 Java 编排版本使用确定性收尾。部署配置不得重解释已有 Run。
5. 前端继续以 Workflow/外部动作持久化事实为准，Turn 完成状态不能覆盖业务状态。
6. 保留历史续跑恢复路径；为拆分边界补单元和数据库验证。

## 验收、回滚、交接

Agent 不运行时成功、拒绝、失败、重试、人工处理和待核验状态均能持久化展示；事务失败无半套投影；重复结算不重复写事实；历史 Run 可恢复。新策略只影响新 Java Run，旧数据兼容读取。完成后记录证据并转 P2。
