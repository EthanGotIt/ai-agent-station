# P6：保留上下文并完成真实模型评测

## 前置条件

Java Workflow 语义稳定。确认 Agent、隔离订单夹具与既定模型凭据可用；仅检查凭据存在/长度，不输出值。

## 执行

1. 保留原始 Items、水位、摘要范围、预算、Tool Result 裁剪和压力触发摘要；不与 Workflow 迁移合并重构。
2. 更新 Live driver：Workflow 确定性收尾后结束当前场景，再创建普通新 Turn 检查历史和事项状态。
3. 两套既定模型配置各跑 12 个现有场景 × 3 次；再各跑 6 类长对话场景 × 3 次：早期请求引用、订单切换、授权事实变化、执行状态变化、大工具结果触发压缩、摘要失效后由 Items 恢复。
4. 可同时容纳的固定历史进行压缩前后配对评估；超窗口场景用持久化事实和预设断言验收。
5. 只存脱敏场景、轮数、决策、Item 类型、交互数、变更数、终止状态、耗时、可用 Token 用量和断言；不存 Prompt/Thinking/原始响应/密钥/请求头。
6. 只一套通过则选通过者；都通过时按路由质量优先，平局且 Flash p95 快至少 15% 才切换，否则保留当前默认；均失败则修复并复测。

## 验收、回滚、交接

安全、授权、幂等与业务事实断言全通过；现有路由终止至少 35/36；长对话至少 17/18，授权/成功事实误判为零。用量缺失记 unavailable；没有真实调用不得记 Live 通过。模型选择独立回滚，评测摘要供 P7 引用。
