# P8：Turn 恢复与 WorkflowTask

## 目标与前置条件

P8 在 P0—P7 的必要环境验收完成后实施。保留 Thread → Turn → Item；一次 Turn 可以跨模型调用、结构化补参、Checkpoint 决策、外部动作等待及结果收尾暂停恢复。

`AgentWorkflowTaskModel` 是现有 `AgentWorkflowRunModel` 的命名迁移，不更改其职责、业务身份或数据关系，不新增业务实体或替代表。Workflow 是确定性处理方式，Command 是独立外部写入身份。

## 执行阶段

1. **基线与命名**：盘点 P5—P7 待完成验收、历史非终态 Run、开放交互和 Command；保留工作区原有改动。将 WorkflowRun 内部类型及文档概念更名为 WorkflowTask。沿用现有数据库表列和 API 路由；历史 `runId`/`workflowRunId` 通过边界映射兼容。命名与行为变更分开提交。
2. **Turn 暂停与恢复**：为新 Turn 固化运行语义版本；持久化当前工具调用、受控参数、批次位置、已完成工具结果、待处理项和累计主动执行预算。新增持久化、可去重的恢复信号。旧 Turn 保持既有行为，不根据当前配置重新解释。
3. **分类型接收输入**：普通消息走 Queue 创建后续 Turn；Steer 使用独立接口携带目标 `turnId` 和幂等键；QuestionCard 答案与 Checkpoint 决策继续使用独立结构化接口、交互 ID、版本及归属校验。它们都可恢复原 Turn，但 Steer 不代替补参或授权。
4. **接通 Command 结果**：Workflow 启动后暂停原工具调用并释放线程。Worker 事务内提交 Command、WorkflowTask、业务结果 Item 和唯一恢复信号。达到自动重试/核验预算后，将明确失败或待人工处理状态回填原工具调用并恢复原 Agent 循环；预算内继续等待，不创建自动续跑 Turn。
5. **Queue／Steer 安全边界**：同 Thread 主动执行保持串行；恢复和交互答复优先于排队消息。Steer 在安全处理点处理，远程命令提交后不得更改参数或幂等身份。若提交前 Steer 改变授权指纹，废弃旧 Checkpoint 并重新确认。取消停止原 Turn 后续处理；已提交命令继续核验，晚到结果不重新激活已取消 Turn。
6. **复合请求与界面**：支持“催发 A 并查询 B”：同批中不依赖 A 结果的只读查询可以执行；依赖 A 结果的步骤待动作结果回填后继续。保持一个开放交互及本期一个写流程边界。前端以持久化 Items 展示排队、Steer、补参、批准、动作等待与最终事实。

## 验收

- 退款、催发货、删除都能在原 Turn 内完成补参、批准、命令等待、结果回填及 Agent 收尾。
- 补参、批准、拒绝、Steer 具备不同输入结构、归属校验、版本校验和幂等行为；不存在文本 Steer 绕过 Checkpoint 的路径。
- 覆盖 Queue 顺序、Steer 与批准竞争、各暂停点重启、重复信号、结算后通知丢失、取消后的晚到结果和工具批次恢复；恢复不重复运行已完成的写入。
- 外部已执行但响应丢失时复用原幂等身份；结果未知不得报告成功或失败。自动预算耗尽后原 Turn 收到待人工核验事实并确定性收尾。
- 模型回复失败不回滚已提交业务事实；复合请求中只读失败不改变写操作状态，写结果完成后依赖查询可继续。
- 历史 Turn/Run、Items、Checkpoint、Command 仍可读；新旧运行语义按持久化版本选择。
- 完成相关单测、HTTP 与隔离 MySQL 验收、完整 Python/Maven/前端矩阵、更新后的 Live 模型评测，以及兼容版本回滚、SSE 断线和桌面/窄屏/移动端浏览器验收。

## 回滚与交接

新语义只用于新 Turn，恢复根据 Turn 持久化版本选择；停止新准入不影响已经创建的新语义 Turn 的恢复。数据库采用增量迁移，保留原表列与命令身份；兼容回滚版本必须能识别恢复数据。每阶段独立验证和提交，更新 `.codex/task-handoff.md`；历史自动化、模型、浏览器和部署证据分别记录，不把旧语义证据冒充新语义验收。
